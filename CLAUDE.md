# Electro Car Racer

A browser racing game in the style of the 80s/90s pseudo-3D racers: split-screen two-player, championship, time challenge, a course builder and online races. It's plain JavaScript (ES modules) on an HTML5 canvas, built with Vite. The browser game has no runtime dependencies; the online race server (`server/`) is Node with Express and `ws`. Every graphic, sound and song is generated in code, so there are no asset files.

The repo folder is still called `lotus-remake`, because the project began as a Lotus III tribute. The game no longer references Lotus anywhere, and nothing new should either: no Lotus names, cars, "R.E.C.S." or "Ultimate Challenge".

## Running and checking

- `npm run dev` starts the dev server, `npm run build` builds into `dist/` (relative `base`, so it can be hosted anywhere), and `npm run preview` serves the build. ES modules don't load from `file://`, so opening `index.html` directly no longer works.
- `npm start` builds and runs the race server (`server/server.js`, port 8090): it serves `dist/` and runs online races on a WebSocket at `/ws`. `npm run server` runs it without building; next to `npm run dev`, Vite proxies `/ws` to it. Without the server, the game is the local one.
- After every change, run these from the repo root:
  - `npm run check` syntax-checks every module under `src/` and `server/`.
  - `npm run smoke` is a headless run in Node with stubbed DOM, canvas and storage (`scripts/stubs.js`). `scripts/smoke.js` builds, races and renders every scenery and every car frame and checks the race mechanics; `scripts/flows.js` then drives the real key handlers through title → menu → championship → 2P time challenge → course-builder race → an online session (the real `server/lobby.js` behind a fake WebSocket, with a scripted second player), asserting the active scene via `window.__ecr`. It catches import, runtime and flow errors, not visual ones. Extend it when you add a scene or flow.
  - `npm run build` confirms that Vite bundles cleanly.
- `install.sh` deploys onto the box that mech-vs-mech's `install.sh` set up (Caddy in Let's Encrypt mode), the way calvo does: `/opt/electro-car-racer`, user `ecr`, systemd unit `electro-car-racer` on `127.0.0.1:8090`, Caddy site `/etc/caddy/apps/electro-car-racer.caddy`, and a timer running `update.sh` every 5 minutes. Both scripts build with `npm ci && npm run build`, so a new runtime dependency needs nothing more there; check them with `bash -n` (and shellcheck if you can).
- The user does all in-browser testing, so never launch a browser or headless Chrome. After each change, list the manual checks to run instead.
- `window.__ecr` (in `main.js`) exposes the current scene name, the current race, the scene table and the settings. Keep it, because the smoke test depends on it.

## Architecture

ES modules under `src/`, with `src/main.js` as the entry point. Folders are listed in dependency order: a module may import from its own folder or from folders above it, never from below, and there are no circular imports.

| Folder | Files | Role |
|---|---|---|
| `core/` | `util.js` (`K`, `U`), `input.js` (`Input`) | Constants (resolution, segment length, camera, speeds, physics step) and helpers: math, seeded RNG `U.rng`, FNV hash, colours, time formatting, `localStorage`. Keyboard (by `KeyboardEvent.code`) and gamepads: `Input.player(idx, two)` returns driving input, `Input.menu()` returns edge-triggered navigation |
| `audio/` | `sound.js` (`Sound`) | Web Audio: per-player electric motor synth, `Sound.fx.*` effects, chiptune sequencer. The context starts on the first user gesture |
| `art/` | `draw.js` (canvas helpers `make`, `flip`, `R`/`P`/`C`/`E` primitives), `scenery.js` (sprite painters), `sprites.js` (`DEF` table, pre-rendering, `get`), `carmodels.js` (each model's rear view and flank `PROFILE`), `cars.js` (3/4 views), `backgrounds.js`, `index.js` (`Art` facade) | Procedural pixel art into cached offscreen canvases. Other folders use only the `Art` facade |
| `world/` | `themes.js` (`THEMES`, `THEME_INDEX`), `track.js` (`Track`) | The 12 sceneries; the course generator (`Track.build(params, opts)`) and the 10-letter course codes |
| `race/` | `specs.js` (cars, motor curve, colours, rival names), `race.js` (`Race`: setup, update loop, laps/checkpoints, ranking), `driving.js`, `ai.js`, `contact.js`, `energy.js`, `power.js`, `shock.js`, `online.js` | Simulation of one race or stage. `driving`/`ai`/`contact`/`energy`/`power`/`shock`/`online` export plain functions that use `this` and are mixed into `Race.prototype`, so write them as methods. Export only functions from them, because every export lands on the prototype, and put shared constants in `specs.js` |
| `render/` | `view.js` (one viewport), `road.js`, `sky.js`, `effects.js`, `hud.js`, `text.js`, `index.js` (`Render` facade) | Segment-based pseudo-3D renderer for a full or split-screen viewport |
| `game/` | `screen.js` (canvas `g`, `W`, `H`, `text`), `state.js`, `ui.js` (menu widgets), `attract.js` (demo race behind menus), `session.js`, `online.js` (`Online`: the browser's side of online races), `touch.js` (`Touch`: on-screen controls), `scenes/*.js` | Game flow. `state.js` holds the saved `settings`/`custom`/`records`, the live `game` object (`scene`, `session`, `race`), the `scenes` registry and `go(name)` |
| `main.js` | entry | Registers the scenes, audio start-up, fullscreen key, the main loop (which calls `Online.poll` every frame) and the `window.__ecr` debug handle |
| `server/` | `server.js` (HTTP + WebSocket, hardening), `lobby.js` (`Lobby`: connections, the one session, message routing and the protocol), `session.js` (`Session`: races back to back, seats, refereeing) | The online race server, in Node. It imports `core/`, `world/` and `race/` and nothing from `render/` or `game/`; `art/sprites.js` skips drawing when there is no `document`, so `race/` stays importable there |

- **Touch controls** (`game/touch.js`) are DOM buttons and gesture layers over the canvas, shown from the first touch and hidden by a key press. On touch the canvas and controls fill the 'stage' (stretched): the viewport less the status bar's safe-area inset at the top, which iPhones fade. In portrait the stage is turned a quarter clockwise so the game uses the full height. `fit()` in `touch.js` measures it into CSS variables, and the insets the stage still overlaps (the camera in landscape, the home bar) into `--l/--r/--t/--b`, which the buttons keep clear of. Keep the iOS status bar `black` in `index.html`: with `black-translucent` a home-screen app's viewport comes up short by the bar and iOS clips everything below it. and `local(e)` maps pointers into the stage frame, so use it for any new pointer handling. The first touch (and any later one while it isn't on) asks for fullscreen, prefixed for Safari too. iPhone Safari has none, so `index.html` and `public/manifest.webmanifest` make the game a full-screen web app from the home screen, `homeIcon` draws its icon, and the title shows the way there while `Touch.homeHint()` says so. `noScroll` blocks every page scroll and zoom gesture, apart from the text field. Buttons hold the keyboard's key codes through `Input.virtual(code, on)`. While racing (`RaceScene`, not paused), a finger dragged sideways anywhere steers through `Input.setSteer` (analog), `Input.setAuto(true)` makes player 1 accelerate unless braking, and the faint racing buttons sit under the right thumb. Everywhere else a tap reaches the scene as `Input.menu().tap` in canvas pixels and counts as `ok`; `rowsNav` turns a tap into picking the row that `rowsDraw` last drew there (or nothing, beside the rows). On touch, `rowsDraw` spreads rows up to 20 px apart when given the height `h` they may fill (it returns the spacing), and `touch.js` shows < > buttons in the menu panel style in the bottom corners whenever rows were drawn (`rowsDrawn`), so menu scenes show `TOUCH_HELP` (from `ui.js`) there instead of keyboard help. A text field (feeding `Input.type`) shows while the scene is `editing`. A new key-driven action needs a button there too.
- **Scenes** are plain objects with `enter()`, `update(dt)` and `draw(dt)`, one per file in `game/scenes/`. They switch with `go('Name')` and reach other scenes only through `scenes.Name`, never through imports. A new scene must be registered in `main.js`. A scene that takes typed text sets `editing` while it does, so the F key doesn't toggle fullscreen.
- **Keep every file under 300 lines.** When one grows past that, split it along a real seam: a new folder member, or a mixin for `Race`.

### Core model

- **Track:** an array of segments, each `K.SEG_LEN` long, with a `curve` value (about ±7 at most), world `y` for hills, roadside `sprites` and road hazards `obs`. Everything about a course is derived deterministically from its params plus seed, via `U.rng(U.hash(code))`. Use the seeded `rnd`, never `Math.random`, inside `Track.build`, or course codes stop reproducing the same course. Hazard groups are placed only where `inSight` says the camera can see them from about 44 segments back; a group that falls just past a crest slides forward or is dropped, so a hazard never appears suddenly behind a hill.
- **Car position:** `travel` is the distance from the start line (negative on the grid, and it keeps growing over laps). `z` is `travel` wrapped onto the track. `x` is lateral position in road half-widths: `±1` is the road edge, and `|x| > 1` is off-road.
- **Simulation:** `RaceScene` runs `race.update(K.STEP, inputs)` on a fixed 1/120 s step. Edge-triggered inputs (`inp.power`) are cleared after the first sub-step, so one key press acts once.
- **Electric drive:** the cars are single-speed EVs, with no gears or RPM. `driveHuman` gives full torque up to `MOTOR_BASE` of top speed and constant power above it (`race/specs.js`). `c.pwr` is the power drawn as a share of the car's rated `spec.kw`, in -1 to 1 (negative is regen when braking or coasting). The HUD kW meter shows it, the limited-energy battery drains and recharges by it, and the motor sound (`Sound.engine`) follows speed and `c.pwr`.
- **Humans vs AI:** humans run `driveHuman` (full physics). AI and finished humans (`autopilot`) run `driveAI`, which follows a target speed, avoids slower cars and `avoid` hazards, and is scaled by `rubberBand(c)` in race mode. Rivals in a race (`rival` in `driveAI`) also race actively, with a per-car personality (`aiAggro`, `aiPhase`): they wander between lanes, cut to the inside of bends, let their pace ebb and flow, draft and overtake early, defend against a human close behind (only if it isn't clearly faster), steer for cells and shocks (`aiPickup`), and check their mirrors so they never swerve into a car alongside or closing in the next lane. On Hard (`AI_ATTACK`, `hunt` in `ai.js`), an aggressive rival up to `HUNT_RANGE` behind a player in the top 3 makes a run at them (at most `HUNTERS` at a time, then it backs off for a while): it targets `AI_ATTACK` above the player's car top speed, and `aiShock` saves shocks for a player at the front. A rival that pulls out to pass keeps that lane (`aiLane`) until it is by. Time-challenge traffic just cruises. That keeps the field around the humans: rivals more than `BAND_DEAD` ahead of the front human ease off, and rivals behind the last human push harder, up to ±`BAND[diff]` (16% Easy, 12% Medium, 9% Hard). Hazard effects (`fx`: `soft`, `crash`, `splash`, `ice`, `boost`, `jump`) mostly apply to humans only.
- **Car sprite frame:** `c.frame` ranges from -2 to 2 (0 straight, ±1 slight, ±2 full lock), and `Art.car` draws a 3/4 view showing the flank on the side the car turns towards. Car geometry for the flank lives in `PROFILE` in `art/carmodels.js`, next to each model's rear-view drawing in `REAR`; keep the two in sync. Car sprites are drawn at 2× that 72×40 layout (`SS` in `art/cars.js`), with gradients, glints and glowing lamps (`shell`, `glass`, `lit` in `carmodels.js`), and carry a 72×40 `mip` that `blit` uses for cars drawn smaller than that. The rear tyres' size (`tyre` in `PROFILE`) serves both views: when the car turns, the flank draws the rear tyres whole and in perspective (treads under the rear face, the near sidewall in the arch) and the rear view leaves them out. The models (`CARSPEC` in `race/specs.js`) take their body styles from real EVs, but never their names or badges. Saved car choices that are no longer models fall back to the defaults in `state.js`.
- **Sprites:** an `Art.DEF` entry gives pixel size `w,h`, world width `ww`, hit-box fraction `hit`, variant count `v`, optional `fx` and `avoid`, and a `draw(g, w, h, rnd, o, v)` painter. Sprites are rendered once and cached.
- **Limited energy** (every race, no option: `race.energy` is set for race mode, so time challenge and the attract demo run without it; every car, so rivals drain by their `c.pwr`, steer for cells when low and can run flat) lives in `race/energy.js`. `placeCells` adds `cell` obstacles (`fx: 'energy'`) when the race is set up, using its own seeded RNG, so `Track.build` and course codes are unaffected. Each car keeps the cells it took this lap in `c.taken`, which is cleared on each new lap; the renderer hides a cell only for the car whose view it is drawing. A cell a rival takes is used up for every car until `ob.backAt` (race time), so players see rivals collect them. `c.energy` is `null` when `race.energy` is off, and every energy code path checks for that.
- **Power-ups** (every race, no option: `race.power`, like `race.energy`; humans only) live in `race/power.js` and follow the same pattern as energy: `orb` obstacles (`fx: 'power'`) are placed at setup and collected per car via `c.taken`. `c.power` (charges held, `null` when `race.power` is off) fires from `inp.power` (edge-triggered) into `c.superT`. Power-ups are a catch-up mechanic: orbs do nothing for places 1–3 (they aren't added to `c.taken`, and the view draws them faded), and `powerShare(c)` (0 in 4th, 1 in last) scales the charges per orb and the length of a charge (`c.superMax`). While `superT > 0`, `boostT` and `immuneT` are held up, `crash` hazards fly like cones, splash/ice are skipped, and `collide` shoves the car being hit.
- **Electro shock** (every race, `race.shocks`; no option) lives in `race/shock.js`: `shock` pickups (`fx: 'shock'`) are placed and collected like the orbs, and a pickup a rival collects is used up for every car until `ob.backAt`, like a cell (online, wire flag 8 tells browsers which rivals can still take one). `c.shock` (0 or 1; `null` outside races and for rivals that don't use shocks, a share set by `AI_SHOCKS[diff]`) fires from `inp.shock` (edge-triggered) or, for rivals, from `aiShock` once a car is within 5000 ahead, at `shockTarget(c)`, the nearest unfinished car ahead within range, whether human or AI. With no target the charge is kept. A hit sets the target's `shockT`, and `Race.update` calls `shocked(c)` for every car, so AI is held to `SHOCK_CAP` of top speed too. Super power clears and blocks it, and the view draws lightning arcs on any car with `shockT > 0`.
- **Modes:** `Race` takes `mode: 'race'` (laps, a grid of 20 cars) or `'time'` (one point-to-point stage with checkpoints that extend `timeLeft`, plus slow traffic). Sessions in `game/session.js` chain races: `champ`, `time` or `custom` (from the course builder); `online` sessions come from `game/online.js`.
- **Player names** (`settings.names`, up to 6 letters and digits via `U.plateName`) go on the car as `c.plate`, which `Art.car(model, col, frame, brake, plate)` paints onto the number plate in a 3×5 pixel font (`GLYPHS` in `art/carmodels.js`); a rival's plate is plain. A named player's `c.name` is the name, otherwise `PLAYER n`. While player 1 has no name, the title leads to `NameEntry` (`game/scenes/name.js`) first, which then goes on to the `Lobby` or `MainMenu` as the title would; Esc skips it.
- **Online first:** the title screen connects (`Online.connect`). If the server answers, Enter leads to the `Lobby`, the online menu, and online is the only mode; if it refuses or is silent for 3 seconds (`CONNECT_T`), to `MainMenu`, the local game (championship, time challenge, course builder, split screen). Going back to the title looks again. A lost connection lands in the `Lobby` with TRY AGAIN and PLAY OFFLINE.
- **Online races:** one session per server, started by the first player (their level) and ended when the last player leaves. `server/session.js` runs the races back to back on random courses, drives the rivals and referees: the race clock, the end of a race (all players finished, or `LAST_CALL` after the winner), the session's points table (`POINTS` per race, players only, sent with the results) and the next course. Each browser drives only its own car, with full physics and pickups, and reports it 20 times a second; every car driven elsewhere is a **puppet** (`c.net`, mixin `race/online.js`) that runs on at its last speed and eases onto reported positions (`drivePuppet`). `race.net` is `'server'` or `'client'`. On a client `race.humans` is just the local car (puppets of other players have `human` set but aren't in it); on the server it is every player's car, so the rubber band and defending work as offline. `progress()` skips puppets (their lap and finish come with their state), and an online race's end comes from the server, never `race.over`. A joining player takes over the last rival still racing (`setDriver`, position and speed kept), and a leaving player's car goes back to a rival. The course goes over the wire as its code and the cars in grid order, so car indexes match everywhere. A car's state on the wire is `packCar`/`applyCar` (travel, x, speed, frame, flags, jumpY, lap, finishTime); anything other players must see goes there. A shock that lands on a puppet goes into `race.outbox` (`shockHit`) and is delivered over the network. The protocol is listed at the top of `server/lobby.js`; the server cleans every reported value (`clean` in `session.js`).

## Rules for changes

- **Everything stays procedural:** no image, audio or font files beyond the Google-hosted pixel font, which falls back to monospace.
- **Internal resolution is 480×300** (`K.W`, `K.H`), upscaled with nearest-neighbour. Menu layouts use absolute pixel coordinates at that size, and the pixel font is 8px per character at size 8, so check that text widths fit.
- **Split screen:** `Render.view` gets a viewport; `h < 200` means split mode, which uses a smaller sprite scale and draw distance. Anything new that's drawn in a view has to work at both sizes.
- **Two players share one race:** the per-player state lives on the car object and in `RaceScene.vs[i]`. Don't add global state for "the player". Online there is one player per browser, and the other players are puppets.
- **Saved data:** `localStorage` keys are `ecr.settings` (including `names`), `ecr.custom` (course-builder state) and `ecr.records` (keyed by course code + `R`/`T`). If you change the shape of stored data, make sure old values still load.
- **Online code runs in two places:** anything in `race/` and `world/` also runs in Node on the server, so it must not touch the DOM or browser APIs at import or in the simulation (sounds are fine: `Sound.fx.*` do nothing without an audio context). Server and browsers must run the same game code, so changes to `race/` or the protocol need both sides deployed together.
- **Course codes:** the 8 params (0–15, letters A–P) plus a 2-letter seed. Any other word is hashed into params. Changing generation in `Track.build` changes every existing code's course, so do it only on purpose.
- **Keep `README.md` in sync** when adding player-visible features, controls or options.
